# Сайт Андріївської різнопрофільної гімназії

Статичний сайт на **Eleventy (11ty)**, готовий до розгортання на **GitHub Pages** з власним доменом.
Контент — прості markdown-файли, які може редагувати вчитель без техпідготовки (напряму або через Decap CMS).

## Швидкий старт

```bash
npm install     # встановити залежності (генерує package-lock.json за потреби)
npm run dev     # локальний сервер http://localhost:8080 з live-reload
npm run build   # продакшн-збірка в /_site
```

Потрібен Node.js 20+.

> **Примітка:** у репозиторії немає `package-lock.json` — він з'явиться після першого
> `npm install` і його варто закомітити в git. Якщо після цього захочете пришвидшити
> встановлення командою `npm ci` (детермінована збірка), вона працюватиме лише за
> наявності закомiченого lock-файлу.

## Структура

```
/src
  /_data          site.json (реквізити, меню, дзвінки), home.json, vstup.json,
                  about.json, schedule.json, transparency.json
  /_includes      layouts/ partials/ macros/ icons/
  /content        news/ teachers/ documents/ gallery/   ← «база даних» сайту
  /assets         css/ js/ fonts/ img/ docs/
  /panel-8f2k     адмінпанель (index.html + config.yml); назва теки = адреса
  *.njk           сторінки: головна, вступ, новини, розклад, прозорість…
  feed.njk        Atom-стрічка новин → /feed.xml
  novyny-indeks.njk   індекс пошуку → /assets/data/novyny.json
  pidpyska.njk    сторінка «як підписатися» → /novyny/pidpyska/
  novyny.11tydata.js  заголовки й адреси сторінок стрічки (обчислюються)
  CNAME           власний домен для GitHub Pages
/tools
  /oauth-worker   OAuth-проксі для входу в адмінпанель
eleventy.config.js
.github/workflows/deploy.yml
```

**Де що редагується.** Тексти сторінок лежать не у шаблонах, а в
`src/_data/*.json` — саме тому їх можна змінювати з адмінпанелі, не
торкаючись коду. Шаблон задає структуру блоків, JSON — слова.

## Вхід модератора (адмінпанель)

Адмінпанель — за адресою **`/panel-8f2k/`**
(`https://new.andriivka-school.zp.ua/panel-8f2k/`).

> **Чому не `/admin/`.** Стандартну адресу перебирають боти-сканери
> цілодобово: кожен такий запит — це спроба знайти вхід. Зайти без прав
> на репозиторій вони однаково не змогли б, але сама сторінка входу
> засвічувала і назву репозиторію, і адресу OAuth-проксі. Тепер її просто
> не знаходять. Це не заміна захисту (захист — права в GitHub), а зняття
> зайвого шуму. Адресу тримайте в закладках, а не в переписці.
>
> **Змінити адресу** можна за хвилину: перейменуйте теку `src/panel-8f2k`
> і виправте обидві назви в `eleventy.config.js` (рядок `addPassthroughCopy`).
> Більше ніде шлях не згадується — саме тому його немає й у `robots.txt`.
Через неї редагуються новини, педагоги, документи, галерея, тексти сторінок,
розклад і реквізити. Кожне збереження стає комітом у git: видно, хто й що
змінив, і будь-яку правку можна відкотити.

### Що бачить модератор

| Розділ | Що редагується |
|---|---|
| **Новини** | створення й редагування новин, обкладинки, категорії |
| **Педагоги** | склад, посади, предмети, порядок у списку |
| **Документи** | публічна інформація «Прозорості» + завантаження PDF |
| **Галерея** | фотострічка «Життя гімназії» |
| **Сторінки** | тексти Головної, «Про нас», «Вступу» |
| **Розклад** | уроки по класах і розклад дзвінків |
| **Налаштування** | реквізити, контакти, меню, метрики, розділи «Прозорості» |

Увімкнено режим перевірки (`editorial_workflow`): збережене потрапляє
не одразу на сайт, а у стан **Чернетка → На перевірці → Готово до публікації**.
Публікує той, хто відповідає за сайт.

### Налаштування входу — один раз

Сайт статичний, тож для входу потрібен маленький посередник —
Cloudflare Worker із теки `tools/oauth-worker/`. Чому саме так, описано
в `tools/oauth-worker/README.md`.

**Крок 1. Створіть GitHub OAuth App.**
GitHub → Settings → Developer settings → OAuth Apps → *New OAuth App*.

- Application name: `Адмінпанель Андріївської гімназії`
- Homepage URL: `https://new.andriivka-school.zp.ua`
- Authorization callback URL: `https://gymnasium-auth.ВАШ-АКАУНТ.workers.dev/callback`

Збережіть **Client ID**, потім натисніть *Generate a new client secret*
і скопіюйте **Client Secret** — його показують лише раз.

**Крок 2. Розгорніть воркер.**

```bash
cd tools/oauth-worker
```

У `wrangler.toml` впишіть свій `GITHUB_CLIENT_ID` і перевірте, що
`ALLOWED_ORIGIN` збігається з адресою сайту. Далі:

```bash
npx wrangler login
npx wrangler secret put GITHUB_CLIENT_SECRET   # вставте secret з кроку 1
npx wrangler deploy
```

Wrangler надрукує адресу воркера, напр.
`https://gymnasium-auth.olexiiv.workers.dev`.

**Крок 3. Впишіть цю адресу в панель.**
У `src/panel-8f2k/config.yml` замініть `base_url` на отриману адресу.
Переконайтеся, що `repo:` вказує на правильний репозиторій.

**Крок 4. Перевірте.** Відкрийте `/panel-8f2k/`, натисніть «Увійти через GitHub».
Має відкритися вікно GitHub, а після дозволу — панель.

### Як видати доступ учителю

Модератор заходить власним акаунтом GitHub — так у кожній правці видно
автора. Порядок:

1. Учитель реєструє безкоштовний акаунт на github.com.
2. Repo → Settings → Collaborators → *Add people* → роль **Write**.
3. Учитель приймає запрошення (лист на пошту) і заходить на `/panel-8f2k/`.

> **Альтернатива для невеликого колективу.** Якщо реєструвати акаунт
> кожному незручно, заведіть один спільний обліковий запис-редактор
> (напр. `andriivka-school-editor`), дайте йому Write і передайте пароль
> тим, хто наповнює сайт. Мінус: у комітах усі правки будуть від одного
> імені, і при зміні складу колективу пароль доведеться міняти.

### Правило, яке легко порушити

Адмінпанель перезаписує JSON-файли **цілком**, лишаючи тільки ті поля, що
описані в `src/panel-8f2k/config.yml`. Якщо додати ключ у `src/_data/*.json`
і не описати його в конфігу — перше ж збереження з панелі його зітре.
Змінили дані — одразу опишіть поле.

Це стосується й полів, які редагуються в іншому розділі: у формі
«Розклад дзвінків» решта ключів `site.json` описана як `hidden` саме
тому, що інакше збереження дзвінків стерло б контакти й меню.

## Як додати новину (для редактора)

Створіть файл `src/content/news/2026-02-01-nazva.md`:

```markdown
---
title: Заголовок новини
date: 2026-02-01
category: Оголошення
excerpt: Одне-два речення, які видно в картці новини.
---
Текст новини звичайною мовою. **Жирний**, списки — все працює.
```

Закомітьте в `main` — сайт перебудується й опублікується автоматично.
Категорії: `Оголошення`, `Навчання`, `Вступ`, `Безпека`, `Підтримка`,
`Поради батькам`, `Життя гімназії`.

**Обкладинка.** Картка новини завжди обрізає її до кадру 16:9. Якщо обкладинка
вертикальна (плакат, інфографіка), додайте `coverPosition: "50% 0%"` — у кадр
потрапить шапка, а не середина. Значення: `50% 0%` (верх), `50% 50%` (центр,
за замовчуванням), `50% 100%` (низ). Поля `coverWidth` / `coverHeight` варто
заповнювати завжди: за ними сторінка новини розуміє, що обкладинка вертикальна,
і показує її вужчою колонкою замість на весь екран.

**Відео з YouTube.** Поле `video` — вставте посилання так, як його скопіювали:
`https://youtu.be/ID?si=…`, `watch?v=ID&t=…`, `/embed/ID` або Shorts. Фільтр
`youtubeId` витягне з будь-якої форми сам ідентифікатор; якщо посилання
незрозуміле, блок не намалюється, а в логах збірки зʼявиться попередження
`[відео] не розпізнав посилання`. Плеєр стає між обкладинкою й текстом.
Необовʼязкові `videoTitle` (напис на кнопці, без нього береться заголовок
новини) і `videoCaption` (підпис під кадром).

До кліку сторінка **не звертається до YouTube узагалі**: у розмітці лежить
звичайне посилання на кадрі 16:9 — ні скриптів, ні кук, ні мініатюри з
`i.ytimg.com`. Натиснули — `main.js` підставляє `<iframe>` з
`youtube-nocookie.com` на місце посилання. Без JS посилання просто відкриє
ролик на YouTube, тож блок не ламається ніколи.

**Файл до новини.** Поле `attachment` — шлях до PDF (презентація, буклет,
положення конкурсу). Під текстом зʼявиться картка для завантаження; поруч
`attachmentTitle` (назва) і `attachmentNote` (напр. «PDF, 4 сторінки, 3,7 МБ»
— розмір варто вказувати, бо люди відкривають сайт з телефона). Файли лежать
у `src/assets/docs/` — там само, де документи розділу «Прозорість», але в
колекцію документів вони не потрапляють: та збирається з
`src/content/documents/*.md`, а не зі вмісту теки.

**Текст в зображенні.** Якщо новина — це плакат чи інфографіка, продублюйте
її текст у тілі новини. Інакше зміст недоступний для скрінрідера, не
індексується пошуком і не читається з телефона.

Простіше — через адмінпанель `/panel-8f2k/` (див. «Вхід модератора»): там та сама
новина створюється формою, з підказками до кожного поля.

**Рубрики.** Поле `category` не просто малює бейдж — воно створює сторінку.
Кожна категорія отримує власну адресу `/novyny/tema/<slug>/` зі своєю стрічкою
й пагінацією; slug транслітерується автоматично («Поради батькам» →
`porady-batkam`). Додали в адмінпанелі нову категорію — рубрика зʼявилась сама,
конфіг правити не треба.

**Скільки новин на сторінці.** Перша сторінка — 10 матеріалів (велика картка
плюс дев'ять у сітці), далі по 9, тобто рівно три ряди по три. Числа задані
константами `NEWS_FIRST_PAGE` і `NEWS_PAGE_SIZE` в `eleventy.config.js`.

**Пошук за текстом.** Поле пошуку над стрічкою фільтрує на клієнті за
даними з `/assets/data/novyny.json` (`src/novyny-indeks.njk`) — заголовок,
опис, категорія й повний текст без розмітки кожної новини. Файл генерується
під час збірки, окремо оновлювати нічого не треба.

**Рубрики у випадному списку.** Замість ряду кнопок — `.topicsfilter`:
кнопка з поточною рубрикою й лічильником, панель зі списком. Це досі звичайні
посилання на `/novyny/tema/<slug>/`, а не JS-фільтр; slug транслітерується
автоматично, нова категорія в адмінпанелі не потребує правок конфіга.

Аналогічно працюють `teachers/`, `documents/`, `gallery/` — поля описані
в `src/panel-8f2k/config.yml`. Контакти, метрики, меню, лінії психологічної підтримки та
посилання на стару версію сайту редагуються в `src/_data/site.json`.

> **Увага щодо YAML:** якщо в заголовку чи описі новини є двокрапка, беріть увесь
> рядок у подвійні лапки, напр. `title: "Тема: підзаголовок"` — інакше збірка впаде.

## Розділ «Прозорість» (публічна інформація)

Структура розділу задається одним файлом — `src/_data/transparency.json`. Він
керує трьома речами одночасно: підменю в шапці, картками на `/prozorist/` і
переліком підсторінок. Додали розділ у JSON — сторінка й пункт меню зʼявились самі.

Кожен розділ має:

| Поле | Що робить |
|---|---|
| `slug` | адреса підсторінки: `/prozorist/<slug>/` |
| `label` | коротка назва в меню й на картці |
| `title` | заголовок H1 підсторінки |
| `intro` | опис під заголовком і на картці |
| `icon` | імʼя файлу з `src/_includes/icons/` без `.svg` |
| `keywords` | підказка в підменю шапки |
| `categories` | порядок підзаголовків усередині розділу |
| `facts` | дані, які не є документами (мова навчання, кількість учнів тощо) |

Документ потрапляє в розділ через поле `section` у своєму markdown-файлі:

```markdown
---
title: Освітня програма на 2026/2027 навчальний рік
section: osvitniy-protses
category: освітні програми
file: /assets/docs/osvitnia-programa-2026.pdf
updatedAt: 2026-08-20
featured: false
---
```

`featured: true` виводить документ у блок «Основні документи» вгорі `/prozorist/`.
Тримайте позначеними 4–6 найзатребуваніших — інакше блок втрачає сенс.

Значення `category` мають збігатися з переліком `categories` відповідного розділу,
інакше документ опиниться в кінці сторінки окремою групою. Ті самі значення
продубльовані в `src/panel-8f2k/config.yml` — при додаванні нової категорії оновіть обидва файли.

**Строк публікації:** документи оприлюднюють не пізніше ніж через 10 робочих днів
після затвердження або змін (ч. 4 ст. 30 Закону України «Про освіту»). Поле
`updatedAt` — це дата затвердження, а не дата завантаження файлу.

**Перевірка файлу.** Документ потрапляє на сайт, лише якщо PDF за шляхом із поля
`file` існує і важить більше за 1 КБ. Так на сайт не пролізе ні бите посилання,
ні файл-плейсхолдер. Пропущені записи видно в логах збірки:

```
[документи] пропущено «Статут…»: немає файлу src/assets/docs/statut-2025.pdf
```

Запис при цьому нікуди не зникає — щойно покладете справжній PDF за тим самим
шляхом, документ зʼявиться на сайті без жодних правок.

## Розгортання на GitHub Pages

1. Запуште репозиторій на GitHub.
2. **Settings → Pages → Source: «GitHub Actions»**.
3. Кожен push у `main` запускає `.github/workflows/deploy.yml` → сайт оновлюється.

### Власний домен

1. Впишіть свій домен у `src/CNAME` (зараз: `new.andriivka-school.zp.ua`).
2. У реєстратора домену створіть DNS-записи:
   - 4 записи `A` для кореневого домену → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - `CNAME` для `www` → `ЛОГІН.github.io`
3. У Settings → Pages вкажіть домен і увімкніть **Enforce HTTPS** (сертифікат GitHub видає безкоштовно).

## Стрічка новин, рубрики й пагінація

Стрічку описує одна колекція — `newsArchive` в `eleventy.config.js`. Вона
повертає не новини, а **готові сторінки**: кожен елемент знає свій список
матеріалів, номер, сусідні адреси й набір вкладок. Шаблон `src/novyny.njk`
лише малює те, що йому дали.

| Адреса | Що показує |
|---|---|
| `/novyny/` | усі новини, сторінка 1 (велика картка + 9) |
| `/novyny/storinka-2/` | усі новини, сторінка 2 і далі (по 9) |
| `/novyny/tema/vstup/` | рубрика «Вступ», сторінка 1 |
| `/novyny/tema/vstup/storinka-2/` | та сама рубрика, наступні сторінки |

**Чому не вбудована пагінація Eleventy.** Вона вміє ділити один список на
рівні шматки. Нам треба ще й розрізати той самий список на рубрики й дати
першій сторінці інший розмір — там велика картка. Порахувати це в JS простіше,
ніж викручуватися в шаблоні.

**Чому рубрики — сторінки, а не кнопки.** Раніше фільтр ховав картки на
клієнті. З пагінацією він ховав би лише те, що потрапило на поточну сторінку, —
відвідувач бачив би «у цій категорії немає новин», хоча вони є на другій.
Тепер кожна рубрика має адресу: працює без JS, переживає перезавантаження,
індексується пошуком і її можна кинути посиланням у чат батьків.

**Заголовки.** У `<h1>` рубрики стоїть просто «Вступ» — шлях видно в хлібних
крихтах. А у `<title>` вкладки — «Новини: Вступ», інакше сторінка сплуталася б
зі сторінкою вступної кампанії. Розводить їх поле `metaTitle`, яке розуміє
`layouts/base.njk`.

## Пошук новин і рубрики у випадному списку

Дві речі, які виглядають як один фільтр, але влаштовані по-різному.

**Пошук** працює на клієнті. `src/novyny-indeks.njk` під час збірки складає
`/assets/data/novyny.json` — заголовок, опис, категорію (і її slug) та
повний текст без розмітки для кожної новини. `main.js` (розділ 9)
підвантажує цей файл один раз, кешує проміс і фільтрує вже його: сторінка
«Новини» показує лише одну «сторінку» пагінації за раз, а шукати відвідувач
хоче по всіх новинах одразу — DOM просто не містить решти.

Пошук зіставляє слова запиту через AND (усі мають знайтися — в заголовку,
описі чи тексті), підсвічує збіги `<mark>`, дебаунсить 200 мс. На сторінці
рубрики звужується до тієї самої рубрики. Без JS поле пошуку взагалі не
показується (`.js .searchbox`) — марне поле гірше за його відсутність.

**Пастка Nunjucks, на яку варто зважати, якщо чіпатимете `novyny-indeks.njk`:**
`{% set x = x.concat(...) %}` усередині `{% for %}` не працює — `set`
усередині циклу створює змінну, локальну для цієї ітерації, і вона зникає
після `{% endfor %}`. Зовнішній `x` після циклу лишився б незмінним (тут —
порожнім масивом), і індекс мовчки зібрався б пустим. Це стосується саме
циклів: той самий патерн у `schema.njk`, але всередині `{% if %}`, а не
`{% for %}`, працює штатно. Рішення — мутувати масив через `.push()`
(оголосити один раз до циклу, не переприсвоювати).

**Рубрики** — `.topicsfilter`: кнопка з поточною категорією й лічильником,
панель зі списком. Досі звичайні посилання на `/novyny/tema/<slug>/`, не
JS-фільтр. Розкриває той самий код, що й підменю в шапці (`main.js`,
розділ 1b, атрибути `data-nav-group`/`data-nav-trigger`/`data-nav-panel`) —
навмисно перевикористано без жодних змін у JS.

## Стрічка оновлень (Atom)

`src/feed.njk` збирає `/feed.xml` — 15 останніх новин із повним текстом.
Посилання на неї стоїть у `<head>`, тож читалки знаходять стрічку самі.

**Людям показуємо не файл, а сторінку.** Картка під стрічкою новин і пункт
у підвалі ведуть на `/novyny/pidpyska/` (`src/pidpyska.njk`), а не на
`/feed.xml`: браузер показує сам файл службовим текстом із кодом, і відвідувач,
який не знає, що таке стрічка, бачить поламаний сайт. На сторінці — пояснення
звичайною мовою, адреса з кнопкою «Копіювати», кроки для читалки й
альтернативи для тих, кому читалка зайва.

**Чому не XSLT.** Класичний спосіб зробити XML читабельним — причепити стилі
через `<?xml-stylesheet?>`. Не робіть цього: Chrome вимикає XSLT 17 листопада
2026 року, Firefox і WebKit оголосили те саме, остаточне прибирання —
серпень 2027.

Тексти в стрічці проганяються через фільтр `absolutizeHtml`: читалка показує
статтю на своєму домені, тож `/assets/img/...` там веде в нікуди — всі
внутрішні шляхи стають абсолютними.

Після змін варто перевірити стрічку на `validator.w3.org/feed`.

## Структуровані дані (JSON-LD)

`src/_includes/partials/schema.njk` додає в `<head>` розмітку Schema.org:

- **EducationalOrganization** — на кожній сторінці: повна назва, ЄДРПОУ,
  телефон, пошта, засновник, адреса, Facebook і YouTube у `sameAs`;
- **WebSite** — тільки на головній;
- **NewsArticle** — на сторінці новини (ознака: заповнене поле `category`);
- **BreadcrumbList** — усюди, крім головної.

Усе складається в один `@graph`, а не в кілька окремих `<script>`: так вузли
посилаються один на одного через `@id` і не дублюються.

Дані беруться з `src/_data/site.json` — окремо нічого дублювати не треба.
Змінили реквізити в JSON — розмітка оновилась.

**Про екранування.** Вивід іде через фільтр `jsonld`, який перетворює `<`, `>`
і `&` на юнікод-послідовності. Без цього «</script>» у заголовку новини закрив би тег
посеред даних. Заразом фільтр викидає порожні поля — краще не мати поля, ніж
мати `null`.

Перевірити: `search.google.com/test/rich-results`.

## Дизайн-система

Всі кольори, шрифти й відступи — у `src/assets/css/tokens.css` (єдине джерело істини).
Палітра: `--base #F5F3EF` (тепла кремова база), `--brand #74BE5C`, `--ink #443334`.

**Про зелений — важливе.** `--brand #74BE5C` із білим текстом дає контраст
2.3:1, а WCAG AA вимагає 4.5:1. Тому зелений розділено на три ролі:

| Токен | Значення | Для чого |
|---|---|---|
| `--brand` | `#74BE5C` | **тільки декор без тексту**: риски, крапки списків, лінія таймлайну |
| `--brand-strong` | `#3F7A31` | зелений текст і посилання на світлому (4.7:1) |
| `--brand-fill` | `#3F7A31` | заливка під білим текстом: кнопки, аватари, бейджі (5.2:1) |
| `--brand-fill-hover` | `#2F5C24` | ті самі елементи під курсором (7.8:1) |

У режимі для слабозорих `--brand-fill` підмінюється на `#2F5C24` (7.8:1),
hover — на `#24491B` (10.3:1), тобто рівень AAA.

Якщо додаєте новий елемент із білим текстом на зеленому — беріть
`--brand-fill`, не `--brand`.

Версія для слабозорих: перемикач у хедері, клас `.a11y` на `<html>`, стан у `localStorage`,
inline-скрипт у `<head>` запобігає миготінню (FOUC).
